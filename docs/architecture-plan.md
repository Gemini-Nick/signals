# 隆小侠系统架构重构：四阶段交易循环

> 版本：v1.0 | 日期：2026-03-07
> 状态：待审批 — 等待用户确认后启动实施

---

## 背景

用户反馈当前模式按技术实现划分（review/sim/backtest），不是按用户目标划分。
经过深入研究职业交易员工作流、量化基金因子管线、缠论实战流程，重新设计系统架构。

**核心发现**：交易是一个四阶段循环，每个阶段的输入/输出/思维方式完全不同。

---

## 一、四阶段交易循环总览

```
┌──────────┐     ┌──────────┐     ┌──────────┐     ┌──────────┐
│  周末策略  │ ──→ │  盘前计划  │ ──→ │  盘中监控  │ ──→ │  盘后复盘  │ ──→ 循环
│ (预判大局) │     │ (预判方向) │     │ (应对信号) │     │ (回顾错误) │
└──────────┘     └──────────┘     └──────────┘     └──────────┘
  思维：事件驱动      思维：完全分类      思维：状态机跟随      思维：归因分析
  输出：事件预案      输出：方向+目标位    输出：实时推送        输出：错误分类
```

### 关键区别

| 阶段 | 本质 | 缠论原文对应 |
|------|------|-------------|
| 周末策略 | **预判** — 大事件会怎么影响市场？ | 「不测而测」：枚举所有可能 |
| 盘前计划 | **预判** — 今天会走哪个分类？目标位在哪？ | 第68课「完全分类 + 分段函数」 |
| 盘中监控 | **应对** — 市场选择了哪个分类？执行预案 | 「当下判断，不预测」 |
| 盘后复盘 | **回顾** — 哪里做错了？哪里遗漏了？ | 「复盘是找到每个操作决策的依据」 |

---

## 二、各阶段详细设计

### 2.1 周末策略 `weekly` — 事件驱动的大局预判

**用户问题**：「下周有什么大事？会怎么影响市场？我该怎么准备？」

**不是**简单的周线结构分析。**是**：
- 拉取下周经济日历（CPI/PMI/FOMC/两会/国常会等）
- 每个重大事件制作预案（鸽派/鹰派/中性 → 对应操作）
- 缠论结构 x 事件叠加：事件可能成为结构破位的催化剂
- 输出仓位建议和行业配置

**输出示例**：
```
══ 周末策略 2026-03-07 (下周展望) ══════════════════

▶ 下周重大事件:
  日期        事件              重要性   影响
  03/10 周一  2月CPI数据         ★★★   全市场
  03/12 周三  美联储FOMC(凌晨)   ★★★★★ 全市场
  03/14 周五  2月社融数据         ★★★   银行/地产

▶ FOMC预案:
  情景A(鸽派): 暗示6月降息 → 成长股利好 → 可加仓科技
  情景B(中性): 措辞不变 → 影响有限 → 不调整
  情景C(鹰派): 推迟降息 → 短期承压 → FOMC前减仓至5成

▶ 缠论结构 x 事件:
  沪深300 日线中枢震荡 → FOMC可能是破位催化剂
    若鸽派 → 向上突破 → 日线三买
    若鹰派 → 向下跌破 → 日线三卖

▶ 下周仓位建议: 当前7成 → FOMC前降至5成
════════════════════════════════════════════════════
```

### 2.2 盘前计划 `plan` — 完全分类 + 方向目标位

**用户问题**：「今天关注什么？方向在哪？目标位在哪？什么条件下操作？」

**核心逻辑**（来自缠论第68课）：不是预测一个方向，而是枚举所有可能走势，每种走势配一个预案。这是**分段函数**：
```
f(price) = 操作A, if 价格进入买点区域
f(price) = 操作B, if 价格进入卖点区域
f(price) = 持有,  if 价格在结构内运行
```

**目标位计算方法**（四种）：
1. **中枢边界法**：ZG/ZD → 第一级支撑/阻力
2. **区间套精度法**：大级别定方向 → 次级别精确定位 → 更小级别精确区间
3. **新中枢形成目标法**：前一中枢ZG → 新中枢ZD 的预估
4. **斐波那契延伸法**：笔的等长/0.618/1.618 投射（辅助）

**输出示例**：
```
══ 盘前计划 2026-03-07 ════════════════════════════

▶ 大势: 分化 (强度+0.11)  风格: 均衡

▶ 沪深300 完全分类:
  当前: 30M上涨趋势, 第2中枢上方, 第3笔延伸中

  分类A: 继续上涨
    条件: 不跌破 ZG2=3850
    目标: 新中枢区 3920-3980
    操作: 持有, 关注30M顶背驰

  分类B: 回调进中枢
    条件: 跌破3850 但不破 ZD2=3780
    目标: ZD2附近 3780-3800
    操作: 减仓, 等中枢下沿买点

  分类C: 趋势反转
    条件: 跌破 ZD2=3780
    目标: 日线ZG=3650
    操作: 清仓

  关键价位:
    阻力: 3980 (笔等长), 4020 (0.618延伸)
    支撑: 3850 (ZG2), 3780 (ZD2), 3650 (日线ZG)

▶ 今日关注列表 (3只):
  标的       当前结构           触发条件           预期操作
  SH.601958  30M二买形成中     15M一买确认@12.35  试探买入, 止损12.10
  SH.600519  日线中枢震荡      30M创新高@1720     追涨, 止损1680
  SZ.000001  15M下跌趋势       等底背驰           不急, 观察
════════════════════════════════════════════════════
```

### 2.3 盘中监控 `monitor` — 信号驱动的状态机

**用户问题**：「现在有什么信号？市场走到了哪个分类？」

**核心逻辑**：盘前计划定义了地图（完全分类），盘中就是**跟踪市场走到了地图的哪个位置**。

不做预测，只做应对：
- 监控操作级别K线 → 笔完成/线段转折/背驰发展
- 当价格穿越分类边界 → 分类状态切换 → 执行对应预案
- 多级别交叉验证：大级别信号 + 次级别精确定位

**输出示例**（实时推送）：
```
[09:45] ⚡ 5分钟底分型确认 @ 3862
  分类状态: 仍在分类A (ZG2=3850未破)
  操作: 观望, 等5分钟二买确认

[10:15] ✅ 5分钟二买触发 @ 3870
  分类状态: 分类A确认
  操作: 可加仓, 止损3850

[11:30] ⚠️ 分类切换! A→B (ZG2=3850被跌破)
  新目标: ZD2=3780
  操作: 执行分类B预案, 减仓
```

**与当前 intraday 的关系**：当前 intraday 已实现 L1+L2+L3 扫描。增强点是：
- 引入「分类状态跟踪」（关联盘前计划）
- 信号推送增加「分类上下文」

---

### 2.4 盘后复盘 `review` — 错误分析 + 信号回放

**用户问题**：「今天发生了什么？哪里做错了？哪里遗漏了？」

**核心逻辑**：不是简单看今天涨跌，而是**归因分析**：
- 逐K线回放今日信号时间线（何时出现/确认/消失）
- 损失分类：A类（系统方差）/ B类（执行失误）/ C类（情绪交易）
- 遗漏分析：系统发出了信号但未操作 → 机会成本多少？
- 盘前分类 vs 实际走势：预判对了吗？

**输出示例**：
```
══ 盘后复盘 2026-03-07 ════════════════════════════

▶ 信号时间线:
  时间    标的       事件         级别   价格   状态
  09:45  SH.601958  二买出现     30M   12.35  ⚡出现
  10:30  SH.601958  二买确认     30M   12.50  ✓确认
  13:15  SH.601958  三卖出现     15M   12.80  ⚡出现
  14:00  SH.601958  二买消失     30M   12.20  ✗消失

▶ 盘前分类 vs 实际:
  沪深300: 预判3种分类, 市场走了分类B → 分类覆盖正确 ✓
  SH.601958: 预判二买触发, 实际触发后又消失 → 结构破坏

▶ 操作评分:
  SH.601958 做多: 执行分 2/5, 类型 B(移除止损)
  SH.600519 未操作: 遗漏 (Omission), 错失+2.1%

▶ 本月统计:
  Type A损失: 60% (正常) | B: 30% (需改善) | C: 10%
  遗漏率: 15% (3/20信号未执行)
════════════════════════════════════════════════════
```

## 三、CLI 设计

```bash
# 四阶段循环 — 对应交易员日常
python run.py plan                                # 盘前计划
python run.py                                     # 盘中监控（默认）
python run.py review                              # 盘后复盘（今日）
python run.py weekly                              # 周末策略

# 历史回放 — 对应量化仿真环境
python run.py replay --start 2026-03-05           # 回放指定日期
python run.py replay --start 2026-03-01 --end 03-07  # 回放一段时间

# 工具
python run.py --index                             # 快速看指数
python run.py import --file 研报.pdf               # 研报导入
```

**向后兼容**：旧 `--mode intraday/review/sim` 仍可用，内部路由到新流程。

## 四、实现路线图

这是一个大型重构，必须分批谨慎实施。

### Phase 1: 信号回放引擎（基建层，所有阶段共用）

**为什么先做这个**：回放引擎是 review / replay / plan 的共同基础设施。

| 文件 | 变更 | 说明 |
|------|------|------|
| `signals/core/replay.py` | **新建** | `SignalReplayer` 逐K线回放，记录信号变化时间线 |
| `signals/dashboard/__init__.py` | **修改** | 添加 replay phase 进度显示 |

核心类设计：
```python
@dataclass
class SignalChange:
    dt: datetime
    symbol: str
    freq: str
    signal_type: str      # "二买" / "三卖"
    action: str           # "appear" / "confirm" / "disappear"
    price: float
    confidence: float

class SignalReplayer:
    def feed_bar(self, bar: RawBar): ...
    def timeline(self) -> List[SignalChange]: ...
    def print_timeline(self): ...
```

### Phase 2: 盘后复盘 `review`

在回放引擎之上构建盘后复盘：

| 文件 | 变更 |
|------|------|
| `run.py` | 新增 `run_review_v2()`，输出信号时间线 + 结构变化 |
| `signals/core/replay.py` | 添加 `print_timeline()` 格式化输出 |

此阶段的 review 先不包含操作评分（需要交易记录系统），聚焦在：
- 信号时间线（自动）
- 盘前分类 vs 实际走势对比（需要 Phase 3 的 plan 输出）
- L1 结构变化摘要

### Phase 3: 盘前计划 `plan`

| 文件 | 变更 |
|------|------|
| `signals/core/planner.py` | **新建** 完全分类生成器：枚举可能走势 + 计算目标位 |
| `run.py` | 新增 `run_plan()` |

核心逻辑：
- 从 CZSC 结构中提取中枢 ZG/ZD → 分类边界
- 笔的等长/0.618 → 目标位
- 区间套精度 → 监控区间
- 输出分段函数式的操作预案

### Phase 4: 周末策略 `weekly`

| 文件 | 变更 |
|------|------|
| `signals/core/weekly.py` | **新建** 周度聚合 + 事件预案生成 |
| `run.py` | 新增 `run_weekly()` |

需要：
- 经济日历数据源接入（AKShare `stock_em_macro_event` 或东财日历 API）
- 事件预案模板
- 信号周度统计（聚合多天的 SignalChange）

### Phase 5（远期）: 交易记录 + 归因闭环

- 交易日志系统（手动录入或券商 API 导入）
- 操作评分（执行分 1-5 + A/B/C 分类）
- 遗漏分析（信号 vs 实际操作）
- 月度/季度统计仪表盘
